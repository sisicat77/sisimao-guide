## 这是什么

旅行里最难的从来不是「找不到地方」，是**决定去哪**。

- 一个人时：收藏了七八家，真要出门反而选不出来
- 几个人时：一个人想去展，一个人想逛街，第三个人全程不说话，最后被代表

司司猫做两件事：

1. **把选择变轻**：把一篇知乎回答里的「值得去吗」，变成「距离 / 排队 / 负评」三个能比较的维度
2. **把决定留下**：永远给两个以上选项，最后一句是问句；不用「多数人同意」压少数人

## 30 秒看什么

演示里最值钱的是第二个镜头，**「以前选过的，被重新拿出来」**：

| 时刻 | 发生什么 |
|---|---|
| 09:20 | 群里一条系统提示：**计划变更 · 公园 1 → 公园 2** |
| 15:00 | 你说「下午不知道去哪了」 |
| — | 猫：「计划变了也正常。**你之前存过的 B 和 C**，都在这附近——」 |
| — | B 走过去 8 分钟，但评论说咖啡一般；C 走过去 12 分钟，不排队 |
| — | 两个都不满意 → 「先看看收藏」→ 自己挑 |

注意它做的**不是重排**：

| 常见做法 | 我们做的 |
|---|---|
| 根据天气 / 拥挤，算一版新行程，覆盖旧的 | 不动计划，只把用户自己存下又放弃的那个选项拿回来 |

因为重排会覆盖用户的原始意图，而「不夺走选择权」才是陪伴的前提。

## 关于这一版（重要）

**这是一个可交互的演示版，不是完整产品。**

| | 现状 |
|---|---|
| 界面与交互 | ✅ 完整可点：组队、收藏、计划、确认、私聊劝、群里收 |
| 对话内容 | **预置脚本**，不调用模型 |
| 数据 | 预置演示数据（虚构地点与评论） |
| 后端 | 无。纯静态单文件，断网可跑 |

**为什么用脚本演示**：黑客松现场最怕网络和额度出问题。先把「交互是否成立」验证清楚，再换真模型——这也是 Roadmap 的第一步。

模型接入的接口、成本与降级策略已经设计完成，见下方 Roadmap 与 [PRD](PRD.md)。

## 三个不

- 不把 2–3 个选项砍到只剩一个
- 不打分、不排名
- 不在群里评理、不公开谁让步了

## 功能

| 功能 | 说明 |
|---|---|
| 组队 | 邀请链接 + 4 位口令，1–5 人；单人 = 1 人团 |
| 收藏池 | 每条标「谁推的」，带必去 / 有空去；同地点自动合并 |
| 提议与确认 | 组长提案，**每个人都点确定**才锁定 |
| 召回 | 计划崩了，只给两个最优，各带一条代价；不满意去收藏里自己挑 |
| 私聊劝、群里收 | 群里吵起来，猫分别私聊；回群只说「A 可以继续走啦」 |
| 计划页 | 点行就地改时间 / 地点；改完即生效 |
| 对比抽屉 | 两个候选 × 维度，只给信号，不给分数 |

## 为什么是现在

- 已有研究证明「动态行程」是成立的需求，但它们的解法是**重排**：算一版新的，覆盖旧的
- 我们试的是**召回**：不动计划，只把用户自己存下又放弃的那个选项拿回来
- 因为重排会覆盖用户的原始意图，而「不夺走选择权」才是陪伴的前提

## Roadmap

- [ ] 接 DeepSeek：对话由模型生成，不再是脚本
- [ ] 知乎链接解析：粘一条回答，抽出可比较的维度
